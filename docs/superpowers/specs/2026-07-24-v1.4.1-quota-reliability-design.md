# AACC v1.4.1 额度与授权可靠性设计

日期：2026-07-24  
目标版本：1.4.1  
分支：`codex/fix-1.4.1-quota-reliability`

## 1. 背景与结论

本设计基于 v1.4.0 发布后的统一评审意见，并逐项对照当前代码与发布状态。
评审提出的 Kimi OAuth 凭据代际竞态、`httpx.Client` 生命周期、授权窗口关闭、
未知额度被显示为 0 和 CI 安全门禁问题成立。评审关于“v1.4.0 尚未发布、下载
链接可能 404”的判断已经过时：当前正式 tag、GitHub Release、DMG 与 SHA-256
资产均存在，因此修复版本为 1.4.1，不回退到 rc.3。

本版本同时增加 Codex 账户额度展示。Codex 本机会话的结构化
`event_msg → token_count → rate_limits` 元数据提供 300 分钟与 10080 分钟窗口，
包括已用百分比和重置时间。AACC 只读取这些结构化字段，不读取、保存或展示
prompt、response、命令和文件内容。

## 2. 范围

### 2.1 本版本实施

- Kimi 凭据 generation/CAS 协议。
- pending 状态禁止普通额度轮询。
- `begin_oauth()` 原子 check-and-set。
- OAuth、刷新、API Key、logout 与 401 清理的迟到结果保护。
- OAuth 兜底异常恢复与单次完成信号。
- OAuth deadline 取设备码有效期与 15 分钟的较小值。
- 所有 Kimi HTTP client 都被确定性关闭。
- 取消按钮、窗口 X、Esc 与应用退出统一取消 OAuth。
- Kimi `OK / PARTIAL / UNKNOWN / STALE` 展示语义。
- Codex 5 小时与周额度读取、校验、过期判断和独立 UI 条。
- CI 的锁文件复现、依赖漏洞阻断、漏洞报告产物与 changed-line coverage 门禁。
- Qt 鼠标测试弃用警告修复。
- 自签名社区构建的双语 SHA-256 与 Gatekeeper 指引补强。
- 发布资产校验脚本，验证 tag、Release、DMG 与 SHA-256 资产。

### 2.2 明确不实施

- `gui.py` 全量拆包。
- 三种发现解析器的强制泛型化。
- 将发现状态 `STALE_SECONDS` 暴露为普通用户配置。
- 全局快捷键自定义。
- 仅为缩小 lock 文件而限制 uv 的跨平台解析。
- 把 SQLite 默认 `timeout=5` 描述为缺陷；当前默认行为已经等待 5 秒。
- 声称已经完成未实际执行的 macOS 13/15 真机测试或 Apple 公证。

## 3. Kimi 凭据一致性

### 3.1 快照与代际

新增仅由 `QuotaService` 持有的凭据协调器。它在同一个可重入锁内维护：

- 当前 generation（进程内单调递增整数）；
- 当前活动 OAuth `flow_id`；
- 磁盘凭据的规范化 fingerprint；
- 凭据读取、替换和清除操作。

`CredentialSnapshot` 包含 generation、fingerprint 和经过浅拷贝的凭据。网络请求
只能使用快照，且请求期间不持有协调锁。

提交规则：

1. 网络请求前取得快照。
2. 请求完成后重新取得锁并重读磁盘 fingerprint。
3. 只有 generation 和 fingerprint 都与快照一致时，才允许替换或清除凭据。
4. generation 已推进或凭据被外部修改时，迟到结果被丢弃。
5. API Key、logout 和新 OAuth flow 都先推进 generation，使所有旧请求失效。
6. OAuth 结果还必须匹配当前 `flow_id`。

generation 保持为进程内协调状态，不改变现有凭据文件格式。AACC 已有单实例
约束；进程间意外修改由 fingerprint 校验覆盖。这样保留现有 0600 原子文件格式，
也避免 logout 为保存 tombstone 而留下伪凭据文件。

### 3.2 状态与流程

`begin_oauth()` 在一个 `_state_lock` 临界区内完成以下操作：

- 若已 pending，直接返回；
- 创建新 `flow_id`；
- 推进 generation；
- 清除取消事件；
- 设置 pending。

普通 `_poll_once()` 在入口和取得 poll lock 后都检查 pending。已经在网络中的旧
poll 即使稍后返回，也必须通过 generation/fingerprint 条件提交与最终快照确认，
不得覆盖凭据、清除凭据、切换授权状态或发布旧额度。

`set_api_key()` 与 `logout()` 都取消当前 OAuth、推进 generation 并使 flow_id
失效。API Key 保存失败时保留磁盘上的旧凭据，根据旧凭据有效性恢复状态并发射
脱敏错误；logout 清除失败时报告错误，不能谎报已退出。

OAuth 结束统一经过一个幂等 finalizer。只有当前 flow 可以：

- 成功提交新凭据并进入 authorized；
- 在失败或取消时退出 pending；
- 发射一次 `oauth_finished`。

兜底捕获 `Exception`，不捕获 `BaseException`，使用 `logger.exception()` 记录
脱敏上下文，并保证线程不会把状态永久留在 pending。

### 3.3 Client 生命周期与 deadline

`_poll_once()` 和 `_oauth_flow()` 都使用 client 上下文管理器。无论成功、HTTP
异常、取消、CAS 失败或持久化异常，`close()` 都只调用一次。

设备码轮询 deadline 为：

```text
now + min(max(expires_in_seconds, 0), 15 minutes)
```

非法或非正有效期在设备授权响应解析阶段失败，不进入轮询。

## 4. 额度数据模型

### 4.1 通用窗口语义

额度窗口以不可变对象表示：

- `used_percent: int`，仅接受 0–100；
- `window_minutes: int`；
- `resets_at: datetime`；
- `observed_at: datetime`。

缺失或非法窗口用 `None` 表示，绝不构造全 0 对象代替解析失败。只有服务端明确
提供合法的 `limit=0`、`used=0` 或 `used_percent=0` 时，UI 才显示 0%。

快照状态：

- `OK`：两个核心窗口都有效；
- `PARTIAL`：仅一个核心窗口有效；
- `UNKNOWN`：没有可验证的核心窗口；
- `STALE`：刷新失败而仍保留上一次成功值，或本地窗口已越过重置时间且没有新值。

### 4.2 Kimi

`QuotaDetail` 仍保留 used、limit、remaining、reset_at 与 percentage，但
`KimiQuota.weekly`、`five_hour` 和 `total_quota` 改为可选。解析器要求 section
是字典，并且至少存在可验证的 limit 以及 used/remaining 组合。畸形根对象抛出
`KimiQuotaError`；部分合法 payload 产生 PARTIAL。

网络刷新失败时 UI 保留上一次成功百分比，将摘要改为“数据过期”，tooltip 显示
错误摘要和最后成功更新时间。首次刷新即失败且无旧值时显示 `--`。

### 4.3 Codex

新增 `codex_quota.py`：

- `CodexQuotaReader` 从 `~/.codex/sessions` 选择最近修改的会话文件；
- 只读取文件尾部有界字节并逆序寻找最新合法 `token_count.rate_limits`；
- 按 `window_minutes` 识别 300 分钟和 10080 分钟窗口，不依赖
  `primary/secondary` 永远保持同一顺序；
- 校验 `used_percent`、`resets_at`、事件 timestamp 和可选 plan type；
- 已越过 `resets_at` 的窗口不继续显示旧百分比；
- malformed、半行、超长行和不支持 schema 均安全降级为 UNKNOWN。

新增 `CodexQuotaService(QObject)`，在独立 daemon 线程中每 10 秒读取一次本机
额度，使用 Qt signal 向 GUI 发布快照。它不访问网络、不读取 Codex 凭据，也不
修改 Codex 文件。读取失败不会终止线程。

Codex 额度服务不依赖当前选中的任务；只要本机有 Codex 会话产生过合法 rate
limit 元数据，就能展示账户级额度。

## 5. UI

顶部显示两条独立额度条：

```text
Codex 额度   5h 18%  [进度]   周 27%  [进度]
Kimi 额度    周 42%  [进度]   5h 10%  [进度]   ¥3.15
```

两条保持各自语义：

- Codex 条只读，不触发授权；点击时立即重新扫描本机元数据。
- Kimi 条保持点击刷新/授权行为。
- `--` 表示未知，不把 progress bar 的内部 0 值解释为真实 0%。
- PARTIAL 只将缺失窗口显示为 `--`。
- STALE 使用灰色状态点并在摘要中显示“数据过期”。
- tooltip 显示每个窗口的重置倒计时、最后更新时间和错误摘要。

`KimiOAuthDialog` 使用幂等 `cancel_once()` 汇聚取消按钮、X 和 Esc。服务成功
完成时调用不触发取消信号的关闭路径。应用退出由 `QuotaService.stop()` 设置
取消事件，并等待 worker 在有界时间内结束。

本批不做 `gui.py` 全量拆包，但新的 Codex 数据读取与后台服务必须放在独立模块，
避免继续把业务逻辑写入 GUI。

## 6. CI 与发布

- 所有 `uv sync` 改用 `--locked`。
- pip-audit 输出 JSON；发现漏洞时作业失败；报告步骤使用 `if: always()` 上传。
- 豁免必须显式记录 CVE、原因、负责人和到期日；本版本不预置空泛豁免。
- PR CI 生成 coverage XML，并用 diff-cover 对 `origin/main` 执行 90% 门禁；
  checkout 使用完整或足够的历史。
- `ruff format --check` 在统一格式化现有代码后启用，格式化作为独立机械提交，
  不与逻辑修改混在同一提交。
- release 资产检查不放在普通 PR 的先决条件中，避免“代码先合并还是 Release
  先存在”的循环依赖；使用手工/发布后脚本验证指定版本的 tag、非 draft Release、
  非 prerelease 标志、DMG 与 `.sha256` 非零资产和下载 HTTP 200。
- 当前发布策略明确称为“自签名、未公证的社区构建”。README 中提供完整
  `shasum -a 256`、Open Anyway 和必要时 `xattr -cr` 分级指引。不得声称
  Gatekeeper 无提示；未来取得 Developer ID 后再启用正式公证路径。

## 7. 测试

### 7.1 Kimi 并发与异常

- 旧 refresh 延迟，新 OAuth 先完成：保留新 OAuth 凭据。
- 旧额度请求延迟后返回 401：不得删除新凭据。
- OAuth 中设置 API Key：保留 API Key。
- OAuth 中 logout：最终无凭据，迟到 OAuth 不得恢复。
- 两线程同时 begin：只启动一个 flow。
- OAuth 保存抛 OSError：退出 pending，发射一次失败。
- 取消发生在 token 返回前和返回后：均不得提交已取消 flow。
- client 在成功、401、HTTP 错误、取消和保存异常路径全部关闭。
- 多轮 poll 的 client 创建数与关闭数相等；macOS 有 `num_fds()` 时增加有界
  回归测试，避免依赖绝对 FD 数。

### 7.2 额度解析与 UI

- Kimi 明确 0 与缺失、畸形、部分 schema 分开。
- Kimi 刷新失败保留旧值并标记 STALE。
- Codex 300/10080 分钟窗口正确解析。
- Codex primary/secondary 对调仍按 duration 识别。
- Codex 百分比越界、时间非法、半行和缺字段显示 UNKNOWN/PARTIAL。
- Codex reset 已过期不显示旧百分比。
- 额度条 OK、PARTIAL、UNKNOWN、STALE 和点击刷新均有 Qt 测试。
- `QTest.mouseClick()` 替代手工构造弃用的 `QMouseEvent`。

### 7.3 全量验证

```bash
.venv/bin/python -m pytest -q
.venv/bin/ruff check src tests
.venv/bin/ruff format --check src tests
.venv/bin/mypy src/aacc
uv sync --locked --extra dev
uv run --with pip-audit pip-audit --skip-editable
```

构建后在当前 Mac 验证 Codex 5h/周额度、Kimi 正常/未知/取消/重新授权、覆盖安装、
`codesign --verify` 和 `hdiutil verify`。未实际执行的 macOS 13/15 与公证结果
保持 Pending。

## 8. 专家复核结论

复核维度：并发线性化、文件原子性、Qt 线程边界、隐私最小化、失败诚实表达、
兼容性、可测试性与发布事实。

结论：设计通过。generation + fingerprint + flow_id 同时覆盖服务内部迟到提交和
意外外部写入；网络请求不持锁；Codex 额度读取保持有界且只解析白名单元数据；
UNKNOWN 与 STALE 不再冒充 0；CI 与发布资产校验分离，避免生命周期循环依赖。
本设计没有把大规模 GUI/发现架构重构混入安全 Hotfix。
