# AACC 1.4.2 Quota and Windows Hardening Design

**Date:** 2026-07-27
**Target release:** 1.4.2
**Platforms:** macOS 13+ and Windows 10+

## 1. Context

AACC 1.4.1 obtains Codex quota only from `token_count.rate_limits` records in
local session JSONL files. This makes the display dependent on a recent Codex
session: when Codex has not run since the current quota window began, AACC has
no fresh record and reports the quota as unavailable.

The current Kimi strip renders the Kimi Code weekly and rolling five-hour
limits. The `/coding/v1/usages` parser already retains the top-level
`totalQuota` object, but the GUI does not render it. Kimi's current product
model has three relevant limits:

- a rolling five-hour Kimi Code limit;
- a weekly Kimi Code limit;
- a monthly membership quota shared with other Kimi membership features.

The Windows port is merged but has not passed a real-machine smoke test. Three
external reviews proposed 17 findings. Each finding has been checked against
the current source, local platform simulations, an isolated PyInstaller module
graph, and the latest GitHub Actions failure.

## 2. Goals

1. Show the current Codex weekly quota without requiring an active or recent
   Codex task.
2. Show concrete local reset date and time directly in every visible quota row.
3. Render Kimi limits in the order `5H`, `WEEK`, `MONTH`.
4. Use one shared quota implementation and layout on macOS and Windows.
5. Repair the confirmed Windows CI, build, type-checking, dependency-audit, and
   configuration-file ACL gaps.
6. Add cross-platform packaging regression checks before release.
7. Preserve honest unknown and stale states; never infer usage or reset times
   that the source did not provide.

## 3. Non-goals

- AACC will not call an undocumented Kimi membership web endpoint to fill an
  empty `totalQuota`.
- AACC will not derive a monthly Kimi percentage or reset date from the
  subscription date.
- AACC will not display Codex's five-hour window. Only a 10,080-minute weekly
  Codex window is accepted.
- The release will not add the proposed Windows `hiddenimports`. An isolated
  PyInstaller analysis proved that `aacc.win32`, `aacc.automation_windows`, and
  `aacc.hotkeys_windows` are already collected from their function-local static
  imports.
- The existing placeholder-token prefix defense will not be weakened.
- The already implemented GUI layout-rebuild guard and Windows limitation
  documentation will not be duplicated.
- Historical `AGENTS.md` material will not be reorganized during release
  hardening.
- Windows foreground-lock workarounds remain outside this release.

## 4. Codex quota data flow

### 4.1 Primary source: Codex app-server

A new focused app-server client will start the installed Codex executable with
`app-server --stdio`, perform the JSONL initialization handshake, then issue
the read-only `account/rateLimits/read` request. It passes no prompt, task,
repository, or conversation content.

The client will:

1. locate an executable from an `AACC_CODEX_EXECUTABLE` override, `PATH`, and
   the exact candidates listed below;
2. start the process without a shell;
3. use a bounded reader queue so a stalled process cannot block the quota
   worker;
4. enforce a ten-second total timeout;
5. terminate and reap the child on success, timeout, parse failure, or shutdown;
6. parse only the response whose request ID matches the rate-limit request.

Candidate discovery checks, in order:

1. `AACC_CODEX_EXECUTABLE`;
2. `shutil.which("codex")`;
3. `~/.local/bin/codex`, `/opt/homebrew/bin/codex`, and
   `/usr/local/bin/codex` on macOS;
4. `/Applications/ChatGPT.app/Contents/Resources/codex` and
   `~/Applications/ChatGPT.app/Contents/Resources/codex` on macOS;
5. `%APPDATA%\npm\codex.cmd` and `%LOCALAPPDATA%\npm\codex.cmd` on Windows.

Only an existing regular file is accepted. A missing or incompatible
executable is a recoverable source failure, not an application startup
failure.

The response parser selects the `codex` entry from `rateLimitsByLimitId` when
present and otherwise reads the backward-compatible `rateLimits` snapshot. It
accepts either `primary` or `secondary` only when
`windowDurationMins == 10080`, `usedPercent` is between 0 and 100, and
`resetsAt` is a future Unix timestamp.

### 4.2 Fallback source: bounded session metadata

The existing bounded local session reader remains as a compatibility and
offline fallback. The composite reader tries app-server first and falls back
to session JSONL metadata when:

- no Codex executable is discoverable;
- the installed version lacks `account/rateLimits/read`;
- the subprocess times out or exits unsuccessfully;
- the response is malformed or has no valid weekly window.

If both sources are unavailable, the result is `UNKNOWN`. A previous displayed
value remains visible as stale only when the service reports an operational
error after a known value; an ordinary valid `UNKNOWN` snapshot clears the
value.

The poll interval changes from ten seconds to sixty seconds because account
quota does not need task-discovery cadence. Clicking the strip still requests
an immediate refresh.

## 5. Kimi quota semantics

`usage` remains the weekly Kimi Code window. The 300-minute entry in `limits`
remains the rolling five-hour window. `totalQuota` is treated as the monthly
shared membership quota and exposed with an explicit `monthly` name in the
internal model.

Each object is parsed independently:

- a valid object produces percentage and optional reset timestamp;
- an empty, missing, or malformed object produces an unknown row;
- an explicit zero is valid and displays `0%`;
- no percentage or reset time is inferred from another window.

The live account checked during design returned valid weekly and five-hour
data but an empty `totalQuota`. In that state, AACC displays `MONTH --` and an
unknown reset value. When the official endpoint supplies `totalQuota`, the same
row displays it without another UI or schema change.

## 6. Quota strip layout

Both strips use a grid rather than one horizontal layout. Every metric has
separate columns for the period label, percentage, progress bar, and reset
text. Column minimum widths and spacing prevent the percentage and date from
overlapping at the existing 420-pixel default panel width.

### 6.1 Codex

Codex has one row:

```text
● Codex 额度   WEEK    9%   [progress]   8月2日 08:40 重置
```

### 6.2 Kimi

Kimi has three rows:

```text
● Kimi 额度    5H      0%   [progress]   7月27日 13:28 重置
               WEEK   72%   [progress]   7月27日 21:28 重置
               MONTH  36%   [progress]   8月24日 13:28 重置
```

The Kimi balance stays visible in the brand column below the summary rather
than competing with reset text. Unknown values use `--`; they never render as
`0%`. The existing click-to-refresh interaction, stale/error coloring,
membership details, source observation time, and diagnostic tooltip remain.

Reset timestamps are converted to the current system timezone and formatted
without platform-specific `strftime` modifiers as `M月D日 HH:mm`. The tooltip
may additionally show countdown text, but the visible row always contains the
absolute date and time when known.

## 7. Windows file protection

### 7.1 Chosen implementation

Use the built-in Windows `icacls` command rather than adding `pywin32`.
`icacls` is available on the supported Windows 10/11 floor and accepts numeric
SIDs, avoiding localized account-name parsing.

A shared file-security helper will:

- keep POSIX descriptor mode `0600` and directory mode `0700`;
- obtain the current Windows user SID with the built-in `whoami` command;
- disable inherited file ACL entries;
- grant full control only to the current user SID, Local System, and the local
  Administrators group;
- invoke subprocesses without a shell and with bounded output;
- raise a dedicated error on lookup or ACL failure.

The protected ACL is applied to the completed temporary file before
`os.replace`. Therefore a failed ACL operation cannot publish a newly written
plaintext token file. The same helper protects:

- `config.yaml`, which contains the localhost API token;
- `kimi-credentials.json`, which contains Kimi API/OAuth credentials.

Security failures are logged at `CRITICAL` with sanitized paths/errors and are
re-raised. The application does not silently continue after failing to protect
a new credential file.

### 7.2 Verification

Unit tests verify exact SID lookup, shell-free `icacls` arguments, failure
propagation, and the guarantee that `os.replace` is not called after ACL
failure. A Windows-only integration test creates a temporary file, applies the
real helper, and asks `icacls` to verify the resulting ACL. The release
checklist retains the stronger manual test: another unprivileged local account
must be denied access.

## 8. CI and packaging hardening

The GitHub Actions matrix remains macOS and Windows.

Changes:

1. Set `QT_QPA_PLATFORM: offscreen` in job-level `env` so both Bash and
   PowerShell execute the same pytest command.
2. Run strict mypy on both matrix legs. The current platform-stub errors in
   `instance_guard.py` are fixed without platform-wide exclusions.
3. Run `pip-audit` on both platforms so marker-selected Windows dependencies,
   including `pywin32-ctypes`, are audited.
4. Upload audit reports with platform-qualified artifact names.
5. Run the native packaging command on both platforms and assert
   `dist/AACC.app` or `dist/AACC/AACC.exe` exists.
6. On Windows, recursively inspect the PyInstaller archive for the three
   platform modules rather than adding unnecessary hidden imports.

`scripts/build_windows.ps1` uses `uv sync --locked --extra dev`. macOS and DMG
build scripts obtain their default version from `uv version --short`; an
explicit `AACC_VERSION` override remains supported for controlled release
builds.

## 11. Testing strategy

All behavior changes follow red-green TDD.

Focused automated coverage includes:

- app-server handshake, timeout, process cleanup, response-ID matching, weekly
  window selection, executable fallback, and local-session fallback;
- Kimi monthly parsing for valid, empty, zero, malformed, and missing reset
  data;
- absolute local reset formatting without Unix-only format flags;
- Codex one-row and Kimi three-row labels, order, values, unknown states,
  stale/error preservation, balance visibility, and click signals;
- Windows ACL command construction, failure-before-replace, and real
  Windows-only ACL verification;
- Windows mypy compatibility and real read-only ctypes smoke;
- CI workflow, build-script dependency group, dynamic version source,
  per-platform audit artifacts, and package output assertions;
- bilingual documentation consistency.

Local macOS completion requires:

```bash
.venv/bin/python -m pytest -q
.venv/bin/ruff check src tests
.venv/bin/ruff format --check src tests
.venv/bin/mypy src/aacc
.venv/bin/mypy --platform win32 src/aacc
```

The macOS package must build and pass `codesign --verify --deep --strict`.
Windows hosted CI must pass tests, strict mypy, pip-audit, and PyInstaller
packaging. Windows 10/11 real-machine smoke and multi-user ACL verification
remain explicit release gates.

## 12. Release policy

The existing `v1.4.1` tag and release are immutable. These changes target
`1.4.2`.

No `v1.4.2` tag or release is allowed until:

- all accepted automated changes are merged and CI is green on macOS and
  Windows;
- both native package builds succeed;
- Windows 10/11 real-machine checklist items are recorded as passed;
- another unprivileged Windows user is confirmed unable to read the protected
  AACC configuration and Kimi credential files.
