# AACC 1.4.4-rc1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task with verification checkpoints.

**Goal:** 修复 1.4.3 main 合并后暴露的 CI 契约问题和可复现的状态、安全、SQLite 与发布透明度缺陷，产出可审计的 AACC 1.4.4-rc1 候选版。

**Architecture:** 保持现有“发现/解析 → TaskState → StateMachine → TaskManager/SQLite → GUI”边界；只在证据来源和状态决策处收紧语义。保持 AutomationExecutor 单消费者模型，增加目标唯一性与注入前复核，不重写平台自动化。发布证据使用仓库锁文件、测试、CI 和双语文档，明确区分托管 Windows Server 与消费级 Windows 10/11。

**Tech Stack:** Python 3.12+, PySide6, Pydantic, SQLite, FastAPI/Uvicorn, httpx, pytest, Ruff, mypy, GitHub Actions, PyInstaller/Inno Setup。

## Global Constraints

- 不修改或删除主工作区已有的 AGENTS.md、.superpowers/sdd/*.md、summit202608-1/、release-output/ 用户材料。
- 每个行为修改先增加失败测试，再写最小实现；所有新增改动行保持 CI diff-cover ≥90%。
- 版本顺序：src/aacc/__init__.py → pyproject.toml → uv lock → 双语 CHANGELOG → 双语 docs/release-notes-1.4.4rc1.*。
- 不宣称真实 Windows 10/11、真实 OAuth、Accessibility 或公证完成，除非有可复核人工证据。
- 不引入未在设计中批准的网络服务、远程遥测、凭据上传或自动执行命令。

- [ ] **Step 2: Implement explicit OpenCode status precedence**

Evaluate in this order:

1. tool/pending → WAITING_APPROVAL.
2. tool/running and active stream parts → RUNNING.
3. tool/failed, tool/error, tool/rejected → ERROR.
4. tool/cancelled/tool/canceled → CANCELLED.
5. explicit step-finish or completed tool evidence → COMPLETED.
6. no process without explicit completion → STOPPED.
7. live process with stale/unknown evidence → existing WAITING_INPUT/IDLE fallback.

Keep privacy constraints: do not read prompt, response, command, or reasoning text.

- [ ] **Step 3: Make Kimi termination type-safe**

Change the wire helper from bool | None to a small event result distinguishing COMPLETED, CANCELLED, and UNKNOWN. Preserve normal usage.record as completion and map turn.cancel to cancellation.
