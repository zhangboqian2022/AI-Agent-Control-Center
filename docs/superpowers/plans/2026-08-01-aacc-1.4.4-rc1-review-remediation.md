# AACC 1.4.4-rc.1 Review Remediation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task with verification checkpoints.

**Goal:** Address the technically verified findings from the final AACC 1.4.4-rc.1 review without broadening the product's local-only security model or making unsupported platform claims.

**Architecture:** Keep configuration writes atomic and platform-specific: POSIX continues using an open parent directory, while Windows uses a native handle-anchored rename and rejects unsafe paths. Keep the single local Bearer token and existing API behavior, but make its keyboard-injection consequence explicit in GUI and documentation. Add runtime loopback enforcement, broker path normalization, and reproducible CI evidence metadata.

**Tech Stack:** Python 3.12+, PySide6, Pydantic, FastAPI/Uvicorn, ctypes/Win32, C++17 broker, pytest, Ruff, mypy, GitHub Actions.

## Global Constraints

- Do not modify the user's dirty primary checkout or delete `summit202608-1`, `summit02`, `release-output`, or existing review material.
- Every behavior change starts with a failing test and must preserve the existing full test suite.
- Do not claim consumer Windows 10/11 hardware validation, Apple notarization, Windows signing, or a successful adversarial test unless fresh evidence exists.
- Preserve the existing local loopback-only API and one-time token rotation semantics; this review does not authorize a token capability redesign.
- Keep `uv.lock` synchronized whenever project metadata changes.
