# AACC 1.4.4-rc1 评审决策记录

本记录将四份评审中的可复现缺陷与范围争议分开。所有结论均已对照当前
`main` 合并结果和 RC 工作树复核后再实施。

| 评审项 | 决策 | 证据 / 处理 |
| --- | --- | --- |
| OpenCode 完成后仍显示蓝灯，强制结束也不退出 | 接受 | 部件历史和进程存活共同决定状态；只有明确完成证据才完成，取消/失败分开，进程消失显示 STOPPED。 |
| Kimi 取消被判为完成 | 接受 | `turn.cancel` 映射为 CANCELLED。 |
| 终态被旧的活动候选覆盖 | 接受 | 通过时间戳和运行边界检查拒绝过期的终态重启。 |
| 发现服务重复初始化 SQLite | 接受 | 运行时注册仅在新任务时执行 `INSERT OR IGNORE`。 |
| Adapter 注册表存在但没有接入运行时 | 部分接受 / 明确边界 | 已接入配置的非原生任务，但只提供进程级证据；Agent 专属完成语义仍不在范围内并已写入文档。 |
| 键盘注入可能错窗 | 接受 | macOS/Windows 都要求唯一目标，并在注入前复核前台身份，失败即拒绝。 |
| 配置父目录 TOCTOU | 部分接受 | POSIX 保存使用锚定目录描述符和相对替换；Windows 保留原始写入句柄做身份核对，使用带 DELETE 权限的句柄发布，并从已验证的非 reparse 父目录句柄取得 canonical final path；不宣称完全消除竞态。 |
| Kimi Daimon INFO 日志暴露绝对路径 | 接受 | INFO 只记录候选数量。 |
| 当前仓库缺少 `uv.lock` | 拒绝 | 当前 Git 历史和 CI 均要求且包含受跟踪的 `uv.lock`；该说法来自旧送审副本。 |
| 托管 Windows 10/11 等于真机验证 | 拒绝 | CI 标注与清单都明确了证据边界。 |

对于已经被后续版本测试和发布说明覆盖的 v1.2 历史问题，不再把它们重新列为
本 RC 阻塞项。尚需人工验证的内容会明确列出，不用自动化结果代替。
